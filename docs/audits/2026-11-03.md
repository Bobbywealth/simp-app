# SIMP audit and desktop/mobile hardening, November 3, 2026

## Implemented

- Fixed production API/frontend origin configuration: the web app used a cross-site onrender API origin with a SameSite=Lax refresh cookie, so reloading lost the login. Use api.mysimp.com and mysimp.com, preserving HttpOnly cookies.
- Added a desktop workspace at 1024px+: persistent sidebar, contextual header, wider page layouts, desktop conversation pane, multi-column home/settings/experiences. Mobile keeps the existing five-tab app navigation.
- Restored direct desktop access to Overview, Experiences, Discover, Matches, Messages, Live, Profile, Settings, Notifications, and privileged moderation.
- Moved Host and install controls above mobile navigation; added pressed-state semantics for experience filters and a skip-to-content link.
- Replaced fabricated Home activity, streaks, interests, peak times, and fake person recommendations with actual account metrics and neutral editorial content. Partial API failures no longer erase every metric; unknown is not zero/100%.
- Added matches/conversations pagination and deduplication. No-photo matches use initials, not unrelated stock portraits.
- Reconciled unread badges with the server on inbox updates, reads, reconnects, focus, and navigation. Fixed message sender detection and duplicate events.
- Switched chat sending to acknowledged, idempotent REST persistence while preserving live socket updates. Restore unsent drafts, rejoin rooms on reconnect, and update badges on reads.
- Fixed JWT expiry parsing and socket reconnection/token updates.
- Preserved intended internal destination through login; rejects external/unknown return URLs. Super-admin frontend access now matches backend authorization.
- Added useful messages for non-JSON/proxy API failures.
- Fixed signed email webhook raw-body parsing order, added timestamp replay bounds, and forwarded persistence errors to Express error handling.
- Removed the broken offline swipe replay (Cache.put with POST, wrong API origin, missing bearer auth, and deletion even on HTTP failure). Failed/offline swipes roll back and clearly report not sent.
- Made PWA updates wait for Refresh, added a working SKIP_WAITING handler, and moved validated notification routing to the app root. Removed manifest entries advertising missing routes or placeholder store IDs.
- Enforced blocked-user direct experience access, hid inactive events/hosts in browse, and restricted exact venue/logistics to the host and approved guests.

## Verified before deployment

- Frontend and backend TypeScript checks: pass.
- Frontend ESLint: no errors; existing warnings remain.
- Native source-based regression suite: 77 tests pass. Run from the repository root: `node --test scripts/audit-regressions.cjs`, or `cd frontend && npm run test:audit`.
- Tests use actual TypeScript modules, React/Testing Library, Express/Supertest, and mocked databases/providers. They never send real messages or touch production data.
- Live authenticated reads: profile, completion, preferences, prompts, interests, matches, conversations, unread counts, discovery, live streams, experiences, hosted/joined plans, notifications, verification, blocks, legal status, sessions. HTTP 200.
- A member cannot read admin stats (403). Unauthenticated profile, conversations, admin, and experiences reject access (401). Nonexistent match/conversation/experience returns 404.
- No active live streams before deployment.

## Remaining limitations / not represented as passed

- EMAIL_PROVIDER=console: actual signup-verification/password-reset email delivery is not configured. No third-party account or sender was silently changed.
- Real iOS/Android camera, microphone, native push, Sign in with Apple, and two-device LiveKit audio/video require device/provider acceptance tests. In-app/API checks are not proof of media delivery.
- SIMP still needs dedicated Twilio ownership/configuration rather than the shared Lionstone account. No credentials or spending were changed for this audit.
- Original Vite/Vitest runner is blocked by this Mac's native tooling execution. A separate native Node regression suite was added and executed; do not claim the original suite passed.
- No production account deletion, reporting/blocking of real members, invitations, outbound messages, or real events were created as test side effects.
- Separate landing-page concept remains unpublished; this release only changes the existing app.
