# SIMP routed administration

## Pages
- `/admin`: real account/platform counts and integration health.
- `/admin/users`: search, status filters, cursor pagination, reason-required moderation and timed suspensions. Super-admin-only role controls; self-edit and last-owner protections.
- `/admin/user/:id`: selected profile and photos, active refresh sessions, audited photo removal and session revocation. No authentication secrets in responses.
- `/admin/reports`: filter, review, action, dismiss and notes, with pagination.
- `/admin/verifications`: signed private-selfie review, approval/rejection, notes and queue pagination.
- `/admin/live`: all active streams, recording review, confirmed media-provider termination and audit.
- `/admin/broadcasts`: targeted composer with confirmation and paginated history. Dispatched is not described as delivered.
- `/admin/experiences`: search and audited visibility controls. Hiding does not cancel existing guest arrangements.
- `/admin/waitlist`: searchable, paginated signup records, without IP/user-agent fields.
- `/admin/analytics`: period-filtered recorded funnel counts and conversion rates, without obsolete purchase metrics.
- `/admin/audit`: paginated cross-user moderation history and operation metadata.
- `/admin/email`: searchable provider delivery-event history.
- `/admin/health`: database/integration readiness and setup gaps. No secret-editor or fake enablement switches.

## Safety and implementation
- ADMIN/SUPER_ADMIN enforced on the server and UI. Role changes require SUPER_ADMIN. No account was promoted as part of this build.
- Required reasons, end dates, confirmation on disruptive operations, transactional role/audit updates, and local auth-cache invalidation.
- Bans/suspensions terminate configured media rooms before reporting success and disconnect active sockets.
- Photo removal persists a cleanup job in the same transaction; provider failures are retried by the existing cleanup worker.
- Verification/report responses no longer include full user authentication records.
- Failure of overview stats does not disable the rest of admin. Pages have loading/error/empty/retry states.
- Public hosting explicitly sets isActive=true so new experiences are discoverable; no production records were rewritten.
- Uses existing Prisma models. No schema migration, provider configuration change, paid service, or outbound broadcast was performed.
